# Aura AI — Authoritative technology stack

> **Status:** Accepted architecture baseline. This document records the owner-selected major technology lines and replaceable provider boundaries for Aura Core, Aura Web, Aura Wall, voice satellites, and Aura Observatory. It is documentation only; it does not scaffold packages, services, manifests, deployment files, or runtime contracts.
>
> **Decision date:** 2026-10-04 · **Related work item:** `AURA-0006` · **Accepted decisions:** [ADR-0012](../adr/0012-python-angular-tailwind-toolchain.md)–[ADR-0016](../adr/0016-api-realtime-pwa-and-voice-protocols.md)

## Authority and version policy

The architecture handover, this matrix, and the applicable accepted ADRs are authoritative for technology direction. The feature catalogue remains an envisioned capability catalogue: a mapping below does not create scope, priority, an implementation sequence, or a delivery commitment.

Only supported major lines are declared here. Exact package and image versions belong in future `uv.lock`, `pnpm-lock.yaml`, container image references, and deployment configuration. Dependency updates must retain the major-line intent, pass the repository checks, and preserve the replaceable boundary. A material change to a language, framework, data authority, protocol, trust boundary, or provider role requires a new ADR; a patch or minor update within an accepted major line does not.

The platform is homelab-first and local-first. Python and strict TypeScript are the only implementation languages currently approved. A third language requires a measured capability or performance need, an ownership decision, and an accepted ADR. Data, credentials, model weights, recordings, and private evaluation content are never committed to source control.

## Technology matrix

| Area | Authoritative choice | Boundary and rationale |
|---|---|---|
| Languages | Python 3.14 for Core services, workers, schedulers, CLI, evaluation, and voice satellites; strict TypeScript for web clients | Keep domain logic in shared Python use cases and client behavior in typed frontend libraries. No third language without evidence and ADR. |
| Python workspace | `uv` | Owns Python environments, dependency resolution, and future lockfile pinning. |
| Python HTTP/API | FastAPI, Pydantic 2, pydantic-settings, HTTPX | FastAPI exposes transport; Pydantic validates settings and DTOs; HTTPX is an adapter client. Domain rules remain below routes. |
| Python persistence | SQLAlchemy 2 async, psycopg 3, Alembic | PostgreSQL is authoritative. Each service owns its schema and migrations; async I/O does not change ownership rules. |
| Python CLI/logging/quality | Typer, structlog, Ruff, Pyright, pytest, pytest-asyncio, Hypothesis | Thin CLI entrypoints, structured logs, static checks, unit/integration/property tests. Exact versions are lockfile concerns. |
| Web runtime/workspace | Node 24 LTS, Angular 22, Nx 23, pnpm 12 | Angular applications compose shells; Nx libraries hold feature behavior; pnpm and Nx define workspace boundaries. |
| Web styling and UI | Tailwind 4, Angular CDK, Angular Signals and RxJS; NgRx Signal Store only for complex shared state | Tailwind and CDK are library-neutral UI primitives. Signals/RxJS are default state tools; NgRx is not a blanket requirement. |
| Web resilience/content | Workbox 7, policy-gated Dexie/IndexedDB, Marked + DOMPurify, Shiki | Workbox caches public/static shell assets only by default. Authenticated responses, transcripts, attachments, and drafts require policy-defined principal binding, encryption, expiry/deletion, logout/account-switch clearing, and kiosk behavior. Markdown is sanitized before rendering; code highlighting is presentation only. |
| Web visualization/testing | Apache ECharts 6, Storybook, axe, Vitest 5, Playwright | ECharts serves client visualizations; Storybook and axe support component accessibility; Vitest and Playwright cover unit and browser behavior. |
| Transactional data | Separate Aura Core and Observatory PostgreSQL databases | PostgreSQL owns business truth and migrations. Observatory never reads Core tables. |
| Vector indexing | pgvector initially, behind an internal port | A dedicated vector database is considered only after documented benchmark thresholds and an ADR. Vector indexes are never the source of truth. |
| Durable asynchronous work | Transactional outbox to NATS JetStream | At-least-once delivery, explicit event IDs, schema versions, idempotent consumers. NATS transports messages; PostgreSQL owns business and workflow truth. |
| Cache and coordination | Valkey for ephemeral cache, rate limits, leases, and short-lived session state; PostgreSQL row/advisory locks for transactional coordination | Cache loss must be safe. Coordination affecting business truth is PostgreSQL-owned. |
| Scheduling and workflow state | PostgreSQL-owned scheduler/workflow state with Core scheduler and workers | Due work is dispatched through the outbox/transport path; the scheduler is not a second source of truth. |
| Agent execution | Aura-owned runtime contracts, run lifecycle, state, budgets, permissions, tools, jobs, events, models, and persistence; lightweight executor plus optional LangGraph executor | LangGraph is behind an Aura interface for branching, loops, pauses, and resumable graphs. Its checkpoints are executor-internal and reference Aura run IDs. No LangGraph concepts leak into domain contracts. |
| Models and evaluation | Ollama local default; explicit opt-in cloud adapters; deterministic checks first; versioned local judges and human calibration | Cloud calls and cloud judges require policy. Exact model inventory and calibration rules remain open. |
| Objects and documents | Garage production S3-compatible object storage; local filesystem development-only; format-specific Python parsers with isolated Apache Tika fallback | Core owns metadata and authorization. Fetched, parsed, and extension-provided content is untrusted evidence, never policy or instruction authority. Fetchers have no ambient credentials; schemes, destinations, redirects, private/link-local/loopback addresses, size, type, time, and resources are bounded. Parser sandboxes receive no unnecessary network or secret access. |
| Governed web research | SearXNG, HTTPX, Trafilatura, and isolated Playwright fetcher | Search, retrieval, extraction, and browser fetching are distinct adapters with redaction and retention controls. |
| Identity and sessions | Authentik OIDC Authorization Code flow; separate Aura and Observatory clients/audiences; same-origin BFF sessions with HttpOnly Secure cookies | BFF validates issuer, audience, state, and nonce; rotates sessions on authentication/privilege changes; explicit SameSite plus origin-aware anti-CSRF protects every state-changing HTTP command. Tokens stay server-side and bearer credentials never appear in browser storage, URLs, or SSE parameters. |
| Secrets | SOPS with age; runtime file or Docker-secret injection | Secrets stay outside source, prompts, ordinary logs, and tool results. Credential retention remains an open policy decision. |
| Extensions | Isolated processes or containers behind versioned MCP, OpenAPI, or gRPC contracts | Third-party code is never imported into Core. Extensions remain disabled until least-privilege identity, filesystem/device access, network egress, secret delivery, resource limits, and per-extension capability grants are defined. Bare processes require equivalent OS sandbox controls; a process/container boundary alone is not a security guarantee. |
| API/realtime | REST with OpenAPI 3.1; generated Angular and Python clients; JSON Schema 2020-12 for events/tools; SSE for text and run-state updates | Generated clients contain transport concerns only. Cancellation, approval, and retry are HTTP commands. |
| Voice | Python satellites using openWakeWord, Silero VAD, faster-whisper, and an isolated Piper-compatible provider | Satellite streaming uses Protobuf/gRPC; browsers use a WebRTC gateway. Piper compatibility is isolated pending licensing review. |
| Integrations | Home Assistant remains authoritative; Google Calendar is the first calendar adapter with per-user OAuth; Web Push and Home Assistant are initial notification channels | Household sharing is an explicit Aura permission. Provider credentials are scoped and revocable. |
| Observatory telemetry | OpenTelemetry SDKs and Collector, ClickHouse, Prometheus, Loki, Grafana | OTel/OTLP carries governed telemetry; ClickHouse stores high-cardinality observations; Prometheus metrics and Loki logs remain separate. |
| Observatory analysis | Polars, PyArrow, NumPy/SciPy, and ECharts | Analysis libraries serve Observatory workloads only; quality and operational metrics remain distinct. |
| Observatory schema changes | Service-owned versioned SQL migrations for ClickHouse and PostgreSQL | No shared database schema or cross-service table access. |
| Deployment and CI | Docker Compose profiles, BuildKit, Ansible, Proxmox, Nginx Proxy Manager, GitHub Actions, Renovate, Trivy, dependency audits, generated-client drift checks, architecture validators, SBOM generation | These are future operational choices, not files created by this work item. Aura Wall begins as a restricted browser-kiosk PWA. |

## Replaceable boundaries and authority

Concrete providers implement inward-facing ports. PostgreSQL owns Core and Observatory transactional truth; pgvector, Valkey, NATS, Garage, Ollama, SearXNG, Home Assistant, Google Calendar, voice providers, and notification channels remain replaceable at their owning boundary. Authentik is the selected identity provider but does not own Aura household roles or domain authorization. LangGraph is an executor implementation, not an Aura runtime contract. OTel is the telemetry transport convention; Observatory owns analysis data. All fetched, parsed, and extension-provided content is untrusted evidence and cannot grant policy or instruction authority.

Generated clients are transport-only. Domain rules remain in service-owned use cases and frontend feature libraries. Cross-service data moves through versioned OpenAPI/JSON Schema/gRPC/telemetry or controlled job contracts, never shared tables.

## Licensing and privacy cautions

Piper-compatible speech output is isolated until the selected provider's model and software licenses are reviewed. Repository licensing and public/private policy remain explicitly open. Apache Tika is a fallback process with its own dependency and deployment license review. Third-party extensions require a least-privilege isolation profile; isolation is not guaranteed by a bare process/container. Cloud providers and cloud judges are opt-in and must be covered by policy, redaction, retention, and credential controls. Offline IndexedDB/Dexie storage is policy-gated for sensitive drafts and captured content.
